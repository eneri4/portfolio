Game of Life

01 — OVERVIEW

3 instances (RGB) of Conway’s game of life playing infinitely on an 8x8 WS2812B RGB LED grid with cyclic boundary conditions

04 — REFLECTION

This project was challenging partly because there is so little documentation for SystemVerilog. I knew exactly how I would implement Game of Life in Python, but translating that into hardware was a different problem. In Python, each line runs after the one before it, but in hardware everything exists at the same time, so I had to rethink how to visit each pixel and when each value gets updated.

The most valuable learning came from understanding the difference between always_comb, which describes logic that responds immediately to its inputs, and always_ff, which stores values that only change on a clock edge, along with the difference between negedge and posedge clocks. In my design, the neighbor-counting logic runs on the falling edge and the memory updates on the rising edge, which gives each result half a cycle to settle and prevents race conditions. These were small details, but getting them wrong meant the design simply didn't work. It showed me that intuition isn't always enough, and that "boring" work like reading a textbook to understand a language really does matter.

To improve the project, I would add complexity to the rules to create a new variation of Game of Life, such as predator/ prey relationships between the RGB channels, or having cells fade gradually to black when they die instead of disappearing abruptly.
